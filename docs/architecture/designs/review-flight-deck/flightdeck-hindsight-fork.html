hindsight_fork
review-flight-deck spike · 30-branch corpus

What is real. All 30 branches, their commit subjects, branch names, authors and file counts vs. the base come from git history in hindsight_fork. Base c77e2368d is the true git octopus merge-base of all 30 heads. The stage-3 table (arrival, reverse, random, H1, H3) comes from a real chained git merge-tree replay, read-only, no working-tree writes. The two blocked pull requests are real conflicts found by that replay, with real file paths and real diff content. What is approximated. Per-branch file counts are inflated by roughly three weeks and 150 commits of inherited upstream/main history each branch picked up on its own merge schedule — not the size of each change's own diff. Bundle grouping in the recommended path packs the H3 order into fixed-size chunks of six for the layout; the order itself is real, the chunk boundaries are not independently optimised. The auto-merge split, and problem/approach prose for branches outside the two blocked cases, are written from the commit subject and diff stat, not a full read of every diff.
