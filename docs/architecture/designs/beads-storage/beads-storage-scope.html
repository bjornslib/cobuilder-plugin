beads-storage: scope and data schema

Source of record: docs/architecture/adr/ADR-0031-beads-as-the-cobuilder-storage-layer.md and docs/architecture/designs/beads-storage/goal.json. This page presents them with your answers of 2026-10-17. Nothing is locked yet.

1. Why now

Work across a local machine, a cloud session, and several team members drifts apart. Without one central store, the backlog and the program states diverge. Sync of the CoBuilder JSON and markdown files produces complex merges. Success measure (accepted): a fresh session finds the next slice with one bd ready call and zero file reads.

2. Scope

Beads is the master of

  • Programs (custom type program): stage and the Gate 1 to 4 approval dates
  • Epics: state and branch
  • Pull requests: one issue each, blocking every epic it holds
  • Slices: order, state, score, attempts
  • The state of every one of these, including who changed it and when

Beads holds a pointer to a file

  • Design documents: goal.json, intent.json, design directory
  • Rubric evidence under .cobuilder/rubrics/<slug>/evidence/
  • ADR files (no decision issue)
  • Every GitHub pull request fact except its number and its merged bit (ADR-0029)

Out of scope

  • The thread ledger (shared/ledger.py): a reply-channel log, not work-item state
  • Every record that is not a program, epic, slice, or pull request: it stays a file
  • Hindsight initiative pages: stay separate (A2)
  • Any change to the viewer or to the data/index.json shape. build_index.py reads beads and writes the same static index. The viewer reads that file
  • A plugin-shipped MCP server (ADR-0016)

3. Data schema

Solid box: a beads issue, or the central store. Dashed grey box: a file or GitHub record. The gate approvals are fields on the program issue, so no gate issue exists. All cb.* fields live in the one metadata.cb envelope (scalars, paths, and lists of paths only).

5. Resolved

  • Master: beads is master of programs, epics, slices, pull requests, and their states. The issue wins over a file.
  • Writes: bd is required for every state write. Without it, scripts read files and refuse writes.
  • Central store: Dolt-in-git (refs/dolt/data), synced with bd sync.
  • Pull request: its own issue (type task, cb.kind = pr), blocks every epic it holds. It replaces the merge gate and the gate type.
  • Gates 1 to 4 and 4a to 4c: flat scalar fields on the program issue.
  • ADRs: file only, no issue. Hindsight pages: separate. Thread ledger: outside.
  • Owners: shared/beads_seed.py in shared/. bd init runs from implement:start at Gate 3 and from the install command, with --skip-agents --skip-hooks (no agent files and no git hooks in the target repo, per ADR-0016).
  • Success measure: a fresh session finds the next slice with one bd ready call and zero file reads.

6. Open items and unverified claims

Verified 2026-10-17 in a scratch tracker: one task issue with cb.kind = pr blocked two epics, and bd ready hid both until bd close. Flat gate fields on a program issue round-tripped through bd show.
Not verified: a cloud session that holds only a git clone, running bd init and bd sync against refs/dolt/data. The smoke check must pass before E1 closes.
Side effect: a pr issue appears in bd ready until it merges. Consumers filter on metadata.cb.kind.
Open: when gh:pr automation closes the pr issue on merge. A gate stored as n/a (value) or absent (field): I lean to the value n/a.
Not done yet: the three epics in goal.json still read as before (E1 seed, E2 read model, E3 write model). The seed of 15 plans and the Gate 1 to 4 field names are not yet in the epic text.
