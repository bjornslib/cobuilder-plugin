- option: "Gate the viewer refresh on a version check, same as the other two phases"
  rejected_because: "This is the exact bug that motivated the whole mechanism — a bundle's viewer had gone stale and silently dropped diagram support because nothing forced a refresh after the viewer changed without an accompanying version bump."
- option: "Skip the authored-field guard; trust each migration step to only touch what it claims"
  rejected_because: "story.json holds authored, irreplaceable narrative text and paid Gemini TTS/art content in the same document as derived fields — a migration is only safe to run unattended if it structurally cannot touch the authored half by accident, which requires checking every field, not trusting the step's own claim."
forces:
- "`viewer/index.html` is a pure build artifact with nothing authored to preserve, while `story.json` mixes derived fields with hand-authored narrative and paid Gemini TTS/art content in the same file — one migration strategy can't treat both the same way."

## Context

Retroactively extracted from PR #4. As the bundle format gained diagrams and other changes, older committed bundles (including this repo's own `.prodyssey/self/` and its test-fixture bundles) needed a way to self-heal to the current shape, motivated directly by a real incident: a bundle's viewer had gone stale and silently lost diagram support.

## Options considered

1. **One version-gated ladder covering everything, including the viewer.** Rejected — reproduces the exact incident that motivated this work.
2. **In-place JSON transforms with no authored-field guard.** Rejected — unsafe next to hand-authored narrative and paid TTS/art content living in the same file.
3. **Three independent phases, one unconditional, two version-gated, with a guard on the data ladder (chosen).**

## Decision

`migrate_bundle.py` always refreshes the viewer, then steps the layout ladder from `bundle_format`, then steps the schema ladder from `story.json`'s own `meta.schema_version`, comparing every authored field before and after each schema step and refusing to write if anything outside the declared `touches` set changed.

## Consequences

- **Positive:** every mode self-heals a stale bundle before doing anything else; hand-authored content is structurally protected from an in-place migration bug.
- **Constraint introduced:** adding a new schema migration means declaring an accurate `touches` set — an incomplete one causes the guard to reject a legitimate migration, not silently under-check it.
- **Negative / accepted:** a failed guard means "no write happened," not an automatic fix — the maintainer has to widen `touches` or fix the migration function by hand.

## Value delivered

- **New capability:** automatic, safe bundle self-migration across all four modes.
- **Benefit:** removes drift-related support burden without risking paid content.
- **Beneficiary:** developer, operator
