Reading

D2 scored lower than D1, and that interval lies below zero. But arm A moved by +0.068 between the two days with no change, and that interval also excludes zero. So the session bootstrap understates the spread between days, and a difference of this size across days is not a reliable result.

Against its own same-day arm A, D2 gained +0.084, with an interval that spans zero. D1 gained +0.207, with an interval above zero. On this evidence, the v2 proposer with gpt-6.1-terra did not beat the v1 proposer with Muse Wonder, and it may be worse.

Doubts, deviations and open items

  • Two changes at once. D1 and D2 differ in the proposer and in the reflection model. The data cannot say which caused the difference. This is why slice 31 failed criterion C1 (0.0).
  • No rerun. You decided not to rerun D1 or D2. The E8 question stays without an answer.
  • Seed scores differ. The same seed program on the same valset scored 0.640 in the D1 run and 0.677 in the D2 run. This is run-to-run variation, not explained further.
  • Truncation warnings. D2 logged 15 "LM response was truncated" warnings, D1 logged 7. A single live check of one such input returned a complete reply (finish_reason: stop). The cause is unknown. Call rows now record finish_reason and token counts (commits dbcf1c5, eaa4b50), so a future run will show which calls were cut.
  • Unconfirmed data. 91 new stops from think-with-ai and cobuilder-harness wait for your label check. Session 46ffdc01 (trainset) shares 731 records with 7f58085f (test set).
  • Live use needs code. The interpret command has no --program option today, so it cannot load D1 or any saved program. It runs the base interpreter.

Your proposal: live sessions through the Stop hook

You proposed to stop optimising on past sessions. Instead, a light Claude Code integration runs on each Stop hook: it builds the digest, runs the interpreter, and records the steps and the outcome (Notify, AskHuman, and the proposed actions). You then give feedback on sessions that you remember, and that feedback shows which parts to improve.

The parts exist: priority digest stores a digest per session, and priority interpret reads that digest and prints the prediction. Facts that shape the design:

  • A digest and an interpreter call are model calls, which take seconds. A Stop hook that waits for them delays the session. [INFERENCE] The hook must start the work in the background and exit at once.
  • The best tested prompt is D1 (0.660 on the test set). Using it needs the --program option on interpret.
  • The repo process for a new integration is a design record (/architect:design), then slices.
