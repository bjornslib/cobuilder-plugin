What the checks see

Folder density. Code files per folder. The first segment is product code, and the muted segment is test code. The red line is the limit of 15. Your answer 6 keeps the tests in the count, so tests and viewer/src/shell stay over the limit.
Groups inside one crowded folder. shared/tracker_port holds 40 files. A bare count gives GREEN no choice. The name families name the choice: a new beads_* file belongs with the other 14.
Density and cohesion are two axes. Cluster Factor = 2μ / (2μ + edges out + edges in), on import edges. The most crowded code folder is also the most cohesive. The midline is for reading only. It is not a limit.

Review-only table (row 9). The four folders at 0.00 are artifact/scripts (10 files), pr/scripts (6), shell/hooks (6), and shell/pager (5): stand-alone scripts or folders of one kind, so a fixed limit would flag them in error.

Contract drift (row 1). Python ast compares the public surface before and after. A replay example:

The spike on agencheck

agencheck: 3,312 commits, 5,432 files, 1,090 .py, 675 .ts and .tsx. It has no boundary.yaml and no glossary.

  1. Build each Spike row (1b, 2, 4, 5, 8) as a throwaway script.
  2. Run each one on the default branch of agencheck, read only. The files of the last ten merged pull requests count as new.
  3. Label 30 findings for each signal: act, keep, or false. An agent labels, and you check 10 for each signal.
  4. Keep a signal when (act + keep) / all is 50% or more, and it has one act or more. This is the 50% bar in goal.json.
  5. Also run rows 6 and 7 there, to show that they work outside this repo.
  6. Write the result to docs/plans/structure-coaching/spike-signals.md.

Placement: a new E1 slice after the coach tracer bullet. The spike result decides which Spike rows get slices in E1, E2, and E4.

Open questions and unverified claims

  • Each precision value above is a first estimate by Fable, from labels on this one repository.
  • The figures 83.3%, 28.9%, 5.6%, and the odds ratio 1.83 come from the earlier synthesis and were not checked again.
  • The research spec credits directed modularity to Newman and Girvan. The cited paper credits Arenas et al. The DIOE formula is not verified.
  • agencheck is checked out on a branch from 2026-04-13. The spike reads its default branch.
  • Rows 3 and 10 cannot run on agencheck, because it has no boundary records and no glossary.
  • With every file counted (answer 6), VALIDATE will see crowded-folder findings for new test files in tests/. The coach does not, because RED writes the tests.
