Your question: do I run the GEPA-optimised program on arms A and C?

Not quite. The GEPA program runs in arm C only. Arm A is the base program: no demos and no GEPA. The duel compares them, one against the other, on stops that neither has seen.

1. What the three arms are

The arms differ only in the prompt. The model, the judge, the references and the stops are the same.

"Bad replies" means the model reply did not parse or validate (invalid_output). Each one scores 0.

3. Why the holdout duel the rationale

The reason in one line: C's train score is biased, and the holdout is the only unbiased test of C.

The rule, fixed before the run

  • C counts as better only if the interval of C − A sits above 0.
  • An interval that includes 0 is reported as "no evidence".
  • A mean gain below 0 with the interval below 0 means GEPA overfitted.

Method: A and C run twice each on the 30 stops. The scores pair per stop. The bootstrap resamples the 6 sessions, not the stops, because stops in one session are not independent.

4. What the duel cannot show

  • The holdout looks like the train part. Arm C's "Known context" paragraph about the CoBuilder plugin can help there for that reason.
  • A win then shows a gain on your CoBuilder work. It does not show a gain on other projects.
  • I will add a second line for the 9 holdout stops with no mention. The sample is small, so its interval will be wide.
  • 6 sessions give a wide interval overall. I expect about ±0.15 [inference from the train interval].

6. Open points and doubts nothing hidden

  • Judge pass is fragile. 6 of 8 needs pair 4 and pair 2. Pairs 1 and 3 differ in every run. Eight pairs is a small sample.
  • Arm C looks partly overfitted. Its instruction names two option labels from one training stop (one of them in no brief), and has a CoBuilder paragraph that stops mid-sentence. I did not trace where GEPA took these.
  • Arm B has 15 bad replies, arm A has 2. I did not read the replies. The cause is unknown.
  • One run per arm. I have not measured how much one run moves on this setup.
  • GEPA's reflection model is Mercury 3, the model that it improves. Before it was another model.
  • Cut judge replies. Four replies in a bar run, and two in an earlier run, hit the token cap. I do not know how those calls scored.
  • Four notify excerpts are drafts: 36752881/053, 44a2c88e/008, 46ffdc01/001, 46ffdc01/009. The last one is a demo stop of arm B.
