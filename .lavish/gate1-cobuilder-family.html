The problem

All or nothing

Somebody who only wants their pull requests explained also installs the audit corpus, the picture generator, and the viewer. One install carries the whole lifecycle.

Nothing reads the design

The design work records why a change was chosen and what was rejected. Nothing then builds from that record, so the person answers the same questions again when the code starts.

Words that drifted

The same short word means two things depending on which half you are in. The project keeps a table to stop the confusion — a sign the product is shaped wrong, not the words.

The announcement, written first

cobuilder · release notes

Five tools, one family.

Cobuilder is now five separate things you can install. Take the one you need. Architect helps you design a change before you write it, and records why. Implement takes that design and builds it, one small piece at a time, and each piece is checked by something that did not write it. PR opens your pull request, interviews you while you still remember why, and later turns the whole history into a story you can read. Artifact renders any of it as a page you can share. And Full lifecycle installs all four at once, for anybody who wants the whole thing.

The parts are separate, but they are not strangers. A design you record in Architect is the same design Implement builds from, and the same one that shows up in your pull request. You answer the question once.

The gate demands this before the feature exists. If the announcement cannot be written, the wrong thing is being built.

Screens

No new screens no UI work

The existing viewer already renders both designs and pull requests. This work adds no page to it.

One thing a person sees that is not a screen: the install list. Five named entries where there was one. That list is the product surface for this work, and the names carry it — which makes them a product decision rather than a technical one.

Prior art — what was and was not checked

Hindsight is unavailable, not skipped gate deviation

The recall tools are advertised in this session but are not registered, so checkpoint H1 could not run as the workflow specifies. Two substitutes were read instead, and both are recorded so a later session knows what was consulted. The same wall is expected at H2, before Gate 2.

Ask the author, do not infer shaped a metric

Recorded feedback from an earlier session: when the person who did the work is present, ask them rather than reconstructing intent from the diff. This is why the design record exists, and why questions asked twice: 0 is a success metric rather than a nicety.

The viewer stays build-free constraint held

An earlier session chose a framework for the viewer and reversed it, because a published page blocks external requests and everything would need inlining under a size cap. This work adds no page and must not reopen that.

One stale memory, not trusted verified against the tree

A stored memory states that only one skill ships and that the writing skill is deliberately excluded. Four ship today. The memory records what was true when it was written.

Approve Gate 1, or what should change?

Approval moves to Gate 2 — architecture — where the technical shape is read out of the existing code before anything is designed against it. Nothing is built until Gate 4 produces the slice plan and its blind rubrics.
