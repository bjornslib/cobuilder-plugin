# Training Corpus Index: Symptom-Keyed Navigation

This file makes the approximately 170-file training corpus discoverable by
**symptom or situation**, rather than by filename. Use Section 1 when you look
at a problem and need to know which files to consult. Use Section 3 for a flat
lookup by filename.

## Section 2: Per-Directory Map

**`corpus/principles/`**: YAML principle cards taken from canonical software
engineering books.
Artifact format: `id`, `name`, `category`, `sources`, `summary`, `examples`, `heuristics`, `related_tags`.
Consult this directory when you need the theoretical foundation for a design decision or a refactoring.
**`corpus/principles/security/`**: 14 security principle cards. They cover authentication, authorization, injection, XSS/CSRF, SSRF/deserialization, crypto and key management, RBAC/ABAC, audit logging, frontend security, file upload hardening, tenant isolation, API security, layer boundaries, cloud and platform security, and supply chain security.
Artifact format: `id`, `name`, `category`, `canonical_tags`, `sources`, `summary`, `examples`, `heuristics`, `related_tags`.
Consult this directory when you review a codebase for security vulnerabilities, or when you harden a SaaS application.
Coverage gap: no dedicated OAuth/OIDC flow principle, no MFA enforcement principle, and no incident response procedure principle.

**`corpus/refactorings/`**: language-agnostic and language-specific refactoring patterns and smells.
Artifact format: YAML with `id`, `name`, `category`, `canonical_tags`, `sources`, `summary`,
and `examples` with `bad`/`good` code blocks.
Consult this directory when you look at messy code and need the step-by-step cure.
Coverage gap: the root directory covers about 17 smells and mechanics. The `python/` and `react_ts/`
subdirectories hold only README stubs.

**`corpus/reviews/`**: synthetic multi-seam audit tasks with full system descriptions and embedded issues.
Artifact format: Markdown with frontmatter (`id`, `category`, `canonical_tags`, `sources`,
`related_tags`, `severity`) followed by `## Context`, `## Code`, and `## Issues`.
Consult this directory when you train an agent on realistic audit findings, or when you want to see
how several principles interact in a real system.
Coverage gap: heavy weight on Python backends and data pipelines. No frontend or UI
review tasks, no mobile tasks, and no infrastructure-as-code audits.

**`corpus/scenarios/`**: Q&A teaching cards for architectural decision-making and resilience patterns.
Artifact format: YAML with `id`, `name`, `summary`, and a scenario body with `## Scenario`,
`## Constraints`, `## Questions`, and `## Model Answer`.
Consult this directory when you train on decision-making under constraints, or when you need a worked
example of how to apply a principle to a real situation.
Coverage gap: only 7 files total. `data_systems/` and `resilience/` have one file each.
The `legacy/` and `ddd/` directories are empty. No concurrency, no performance optimization,
and no observability-in-practice scenarios exist yet.
